# Drive Agent Teams through command transactions

The Agent Team Runtime exposes one deep `TeamRuntime` interface: callers dispatch typed commands, inspect immutable snapshots and canonical events, or recover by replaying complete event transactions. Agent actions require a process-local, Runtime-issued `AgentSession`; stable Agent IDs remain inspectable but are not execution authority, recovery invalidates old sessions, and the public Team interface exposes no ID-to-session rebind. A later trusted Runtime Kernel recovery seam must rebind non-terminal owners without accepting model- or user-selected IDs. The module owns validation, bounded Event payloads, one-owner state, downward-only Delegation, deterministic Active/Dormant scheduling, failure propagation, and fold construction; Provider, Tool, Workspace, and persistent Ledger adapters remain outside this interface, and the initial in-memory Ledger reports volatile rather than pretending to cross a crash-safe Durability Boundary.
