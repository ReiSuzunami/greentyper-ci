# Drive Agent Teams through command transactions

The Agent Team Runtime exposes one deep `TeamRuntime` interface: callers dispatch typed commands, inspect immutable snapshots and canonical events, or recover by replaying complete event transactions. Agent actions require a process-local, Runtime-issued `AgentSession`; stable Agent IDs remain inspectable but are not execution authority, recovery invalidates old sessions, and the public Team interface exposes no ID-to-session rebind. The trusted core Runtime Kernel owns the durable adapter, gates root admission, and issues one consumable complete bundle of non-terminal Sessions per validated open without accepting model- or user-selected IDs. The module owns validation, bounded Event payloads, one-owner state, downward-only Delegation, deterministic Active/Dormant scheduling, failure propagation, and fold construction; Provider, Tool, Workspace, and persistent Ledger adapters remain outside the Team interface, and plain in-memory commits report volatile rather than pretending to cross a crash-safe Durability Boundary.
