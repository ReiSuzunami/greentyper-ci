# Bind versioned evidence to one candidate

Acceptance and benchmark output uses an explicit positive schema version and binds each result to a candidate ID, source revision, executable SHA-256, configuration or fixture SHA-256, workload identity, workload version, compiled CPU baseline, and machine fingerprint. Raw samples remain present beside derived summaries, output files are created without overwriting prior evidence, and unsupported schema versions fail explicitly. Benchmark Evidence version 2 separates nanosecond sub-timings from unit-neutral gauges; historical version 1 is never silently reinterpreted. Short CI smoke runs prove only that the harness and CPU guard execute; they cannot substitute for the 30-run FMDev suite or Target Machine release evidence.
